## Truth unavailable (no substitution)

- **obs-studio**: `cmake` configure requires FFmpeg 8.0 or newer; Ubuntu 24.04 provides 6.1. Fixed first, in order: the shallow clone had no tags (version detection), ECM, SIMDe. The configure log is in the run directory.
- **rustdesk**: `cargo` must fetch the git dependency `webm` (`libs/scrap`) from chromium.googlesource.com, which this environment's network policy blocks, so no crate was checked and rustc wrote no dep-info. Submodules (`libs/hbb_common`) were initialised first.

## Build setup that was needed (all recorded, none changes the sources codemap scans)

- apt packages: the documented dependencies of each repository (boost, libevent, sqlite, zeromq and Cap'n Proto for bitcoin; leptonica and libarchive for tesseract; webkit2gtk, gtk, appindicator, rsvg, xdo for the Tauri apps; obs-studio's list, ECM and SIMDe), plus `extra-cmake-modules`.
- tesseract and bitcoin: cmake precompiled-header flags are dropped by the generator (see disclosures). 22 bitcoin units stop at generated headers a full build would produce (`bitcoin-build-info.h`, capnp outputs); they contribute the includes seen before the error.
- clash-verge-rev pins toolchain 1.99.1 in `rust-toolchain.toml`; the rust-analyzer component was added to that toolchain. Its `tauri-build` build script refuses to run unless the sidecar binaries listed in `tauri.linux.conf.json`, the `resources` directory and the frontend `dist` exist (their `pnpm prepare` downloads them); empty placeholders were created for those paths so `cargo check` could run. They are not Rust sources and are outside the universe.
- cargo check runs with `--keep-going` so one failing build script does not stop rustc from checking the other crates.

## Truth generator fixes made after seeing results (disclosed)

| fix | why (what the toolchain reports, not what codemap does) | before | after |
|---|---|---|---|
| C/C++: `-fshow-skipped-includes` added to the `clang -H` run | `-H` alone prints a header only when the preprocessor enters it; an `#include` whose header's include guard was already satisfied earlier in the unit is not printed, so a header's own direct includes were missing whenever any earlier file had included the same header. clang reports those with `-fshow-skipped-includes`. | raylib 438 truth edges, 2 fn, 11 fp (precision 0.975); curl 1,662 truth edges, 0 fn, 755 fp (0.688) | raylib 446, 2 fn, 3 fp (0.993); curl 2,047, 0 fn, 370 fp (0.847) |
| C/C++: cmake precompiled-header flags dropped | cmake's commands carry `-Xclang -include-pch <file>.pch` that only a full build produces; with it 215 of tesseract's 260 units failed before preprocessing and the truth was a fragment. The plain `-include cmake_pch.hxx` stays, so the header is read as an ordinary include. | tesseract 667 truth edges, 215 of 260 units failed, precision 0.334 | 2,001 truth edges, 0 failed units, precision 0.999 |
| C/C++: lenient decoding of compiler output | tesseract's clang output contains non-UTF-8 bytes; the generator crashed. | tesseract truth unavailable | (as above) |
| Rust: edge target is the deepest segment that names a module | The first pass took the file defining a path's last segment. For `tauri::Builder` (defined in `app.rs`, re-exported from `lib.rs`) that is the defining file, which no other language in this benchmark uses as the target (Python and TypeScript edges go to the module the specifier names). The rule now walks the path backwards to the first segment rust-analyzer resolves to a module or crate root, and skips paths with no module segment (`Foo::new()`), which depend on the `use` that imported `Foo`. | tauri 1,301 truth edges, 340 fn, 134 fp (recall 0.739, precision 0.878) | tauri 1,157 truth edges, 107 fn, 45 fp (0.908 / 0.959) |
| Rust: `cargo check --keep-going`; rust-analyzer component installed for the pinned toolchain; placeholders for build-script prerequisites | Without these, clash-verge-rev's truth covered 4 files (the crates checked before cargo stopped) or none. | clash-verge-rev truth unavailable | 139 files, 751 edges |

Every affected repository was rerun from scratch after each fix. None of the changes was motivated by codemap's output.

## Minimal repros of codemap behaviour found here (not fixed in this PR, by design)

Each was reproduced with the released `codemap 4.7.1` on a throwaway git repository containing only the files shown, queried with `codemap --json --importers <file> .` from the repository root.

1. **A Rust package with a renamed `[lib]` and a second target loses every module edge.**
   `Cargo.toml`:
   ```
   [package]
   name = "my-app"
   version = "0.1.0"
   edition = "2021"
   [lib]
   name = "app_lib"
   crate-type = ["staticlib", "cdylib", "rlib"]
   ```
   `src/lib.rs`: `mod cmd; pub fn run() { cmd::hello(); }`; `src/cmd/mod.rs`: `pub fn hello() {}`; plus either `src/main.rs` (`fn main() { app_lib::run(); }`) or `build.rs` (`fn main() {}`). Result: `imports: null` for `src/lib.rs` (and for `src/main.rs`). Without the second target, or without the `[lib] name` rename, `src/lib.rs` -> `src/cmd/mod.rs` is reported. This is clash-verge-rev's `src-tauri` package (`[lib] name = "app_lib"`, `build = "build.rs"`, `default-run`), where codemap reports nothing for 139 files.

2. **A `[[bin]]` with an explicit `path` gets no edges.**
   `Cargo.toml` with `[[bin]] name = "run_benchmark" path = "src/run_benchmark.rs"` (and a second such bin); `src/run_benchmark.rs`: `mod utils; fn main() { utils::go(); }`; `src/utils.rs`: `pub fn go() {}`. Result: `imports: null` for `src/run_benchmark.rs`. This is tauri's `bench/` package.

3. **An `#include` resolves to every same-named header in the tree.**
   `main.c`: `#include "common.h"`; `a/common.h` and `b/common.h` both present; `CMakeLists.txt` adds `a` to the include path. Result: `imports: ["a/common.h", "b/common.h"]`. With `compile_commands.json` or the cmake target's include directories the compiler picks exactly one; codemap reports both, and on bitcoin (`<chain.h>` with `src/chain.h`, `src/kernel/chain.h`, `src/interfaces/chain.h`) and llama.cpp (`"common.h"`) this is the whole precision gap. The converse, a suffix match into the wrong directory (`<util/time.h>` resolved to `src/test/util/time.h`), is bitcoin's main source of false negatives.

4. **`super::` references.** On tauri, files whose only reference to their parent module is through `super::` mostly have no edge to it in codemap (18 of 54 that truth has). Not reduced to a minimal repro here; `crates/tauri-bundler/src/bundle/linux/appimage/linuxdeploy.rs` line 6, `use super::{super::debian, write_and_make_executable};`, is a concrete instance (truth: `appimage/mod.rs` and `linux/debian.rs`; codemap: neither).

5. **The auto-written config of a C++ repository drops `.c`.** codemap writes `.codemap/config.json` on first run with an `only` list from the file-type census; for llama.cpp it is `["cpp", "ts", "svelte", "h", "cl"]` and for bitcoin `["cpp", "h", "py", "ts", "cc"]`, so the eleven `.c` files of ggml (`ggml/src/ggml-alloc.c`, `ggml/src/ggml-cpu/arch/x86/quants.c`, ...) and bitcoin's `src/crypto/ctaes/ctaes.c` are never indexed: 53 of llama.cpp's 85 false negatives are includes from those files. Same family as the `.mjs` drop reported for v4.6.4 on ECC. Repro: a git repository with a few `.cpp` files and one `.c` file that includes a local header; after `codemap .` the config's `only` has no `c`, and the `.c` file has no edges.

Scope notes for the reader: curl's precision (0.847) is entirely configuration-conditional includes (`#ifdef USE_WINDOWS_SSPI` and the like), which the pre-registered definition scores against codemap and which no scanner without a configuration can know. llama.cpp's recall splits between the `vendor/` exclusion codemap applies on purpose (20 edges) and the `.c` drop above (53). The conditional-include cases are reported as scope ambiguity, not errors, and the numbers are left as the definition produces them.
